# Forward / Rex 通用弹幕模块更新记录

## 1.0.18（2026-10-25）

- 腾讯下载直接获取弹幕接口，移除仅用于读取标题的播放网页前置请求。
- 修复空预加载结果被保留并在播放时持续返回 0 条的问题；旧空 token 可重新获取。
- 增加腾讯索引、分片完成进度及原始数据耗时日志。
- 正式版 1.0.8 已同步腾讯下载适配、空预加载重试及分片进度，仍保留等待所有来源的方式，可通过旧版构建命令生成同名文件。
- 已通过两种模拟宿主回归，并直连复查《百花杀》第7集。用户反馈 Rex 实机仍存在慢加载，本轮不宣称已解决分钟级等待；原因尚需实际播放日志定位。详见 [诊断记录](TENCENT-1.0.18.md)。

## 1.0.17（2026-10-25）

本次发布基于 GitHub 上的 Forward / Rex 1.0.7，对应提交 `98276c5a747e4402393231a5524f45f7eefd9d3d`。以下为 1.0.7 到 1.0.17 的累计变化，包含中间本地版本的调整。

| 项目 | GitHub 1.0.7 | 通用版 1.0.17 |
| --- | --- | --- |
| 导入文件 | Forward、Rex 分别提供 JS，使用独立模块 ID | 两个播放器导入同一份 `logvar-1.0.17.js`，统一 ID 为 `logvar.danmu`，显示名称仍为 LogVar |
| 爱壹帆来源 | 默认启用，可填写 `aiyifan` | 从模块可用来源中移除，默认来源从 9 个改为 8 个；旧设置中的 `aiyifan` 自动忽略，旧分集中的爱壹帆链接也不再参与请求 |
| 搜索及下载等待 | 并发启动后等待全部来源结束，慢来源拖延后续处理 | 加入阶段预算和来源收集窗口：首个完整有效搜索结果后目标再等 5 秒；首个完整有效弹幕结果后目标再等 10 秒；全部结束则提前返回 |
| 请求与迟到结果 | 没有统一阶段截止和来源结果隔离 | 搜索、下载各设 30 秒预算；单次请求目标最多 15 秒，临近截止缩短。预算过期后停止新请求、回退和后续分片，迟到来源不再加入本次结果或写入分集详情 |
| 弹弹重复详情请求 | 同一次搜索的回退、季度扩展可能重复获取详情 | 同一次回调内复用成功的作品详情，最多 16 项；空详情不缓存，仍可重新尝试 |
| 分片下载失败 | 部分来源可能把失败分片当作空结果，继续输出不完整整集 | 腾讯、芒果、爱奇艺、优酷、B站的整集获取发现分片请求失败时，舍弃该来源本次不完整数据 |
| 自动缓存 | 持久化作品和分集路由记录，没有新版的搜索／原始弹幕缓存层 | 成功搜索缓存 30 分钟，原始弹幕缓存 10 分钟；切换合并／最多模式可复用原始数据并重新处理；相同的在途 GET 和回调合并，减少重复请求 |
| 清理入口 | 没有模块自带的清理入口 | 增加“清理弹幕缓存”，同时清除搜索结果、预加载弹幕、已下载弹幕和来源标签记录；读回校验、更新刷新标记，阻止清理前的旧搜索和弹幕任务写回有效缓存 |
| 去重间隔 | `count` 参数，部分播放器不能直接填写数字 | 改为可输入文本参数，接受 0～30 的数字和小数，空白默认 1；0 为精确时间去重 |
| 同一集切换处理策略 | 对外作品和分集 ID 不包含本次处理策略，播放器可能复用旧结果 | ID 包含版本、处理设置、刷新标记及已确定来源；同一集切换策略或清理后使用新 ID，并按当前策略合并或比较 |
| 作品和分集来源标签 | 来源标签主要来自匹配候选，最多模式也可能显示多个候选来源 | 最多模式只显示实际胜出来源，未知时不猜测；合并保留 `from 人人&弹弹`、`【人人&弹弹】` 格式，不加“合并”“取最多”“候选”等前缀 |
| 当前集预加载 | 选集和实际弹幕结果没有绑定的预加载批次 | 能识别当前集号时，先获取当前集并确定实际来源，返回带来源的作品／分集标签；播放复用同一份预加载结果。过期、清理或配置改变后要求重新搜索选集 |
| 媒体资料匹配 | Forward、Rex 分别配置 TMDB 路径格式 | 通用构建兼容两种路径格式；资料关联的平台获取和标题补充进入同一阶段预算，失败时继续使用标题搜索 |
| 爱奇艺兼容 | 主搜索或分集接口异常后依赖计时器等待 3 秒再重试，无计时器播放器会报错 | 无计时器时最多尝试一次备用官方路径，覆盖搜索空响应、字符串／数字 `-1`，以及分集接口异常；有计时器时保留延迟重试逻辑 |
| 状态隔离与日志 | 复用同一核心，没有新版分阶段耗时记录 | 每次宿主回调使用独立核心；记录各来源结果和耗时、缓存命中、时间轴对齐、合并／比较、排队及返回耗时与形状 |

### 本次入口整理

移除本地测试期间加入的“检测完整弹幕流程”入口及对应函数：播放器界面无法输入作品名称和集数。1.0.7 原本也没有该入口；它不作为本次新增功能发布。耗时日志通过正常搜索、选集和加载弹幕时记录。

### 保留的功能与实际限制

- 保留“合并全部来源”和“仅保留弹幕最多的来源”、媒体资料优先与标题搜索兜底、屏蔽词、B站 Cookie、中文来源名称和未匹配提示；这些已在 1.0.7 中存在，不列作本次新增功能。爱奇艺本地视频 ID 解码也属于已有功能。
- 默认 8 个来源为：腾讯、爱奇艺、芒果、B站、优酷、弹弹play、人人、韩剧TV。填写启用来源仍会替换默认列表，不分优先级。爱壹帆的移除仅针对播放器模块，Android APP 不受此变更影响。
- 5 秒／10 秒是首个完整有效结果之后的等待目标，不是从点击开始计时的加载上限。来源全部结束会提前返回。无计时器时只能在网络请求或来源返回时检查预算；Forward、Rex 的现有检测也未证明 HTTP 超时参数能按时截断，因此不能保证严格的 5／10／30 秒上限。
- 最多模式按归一化、过滤和去重后的整集有效弹幕数量比较；只有本次完成的来源参与。合并也只处理本次完成的来源。耗时日志不包含播放器实际渲染时间。
- 准确的首次来源标签需要播放器提供可识别的当前集号；缺少集号时不猜测。模块不能主动改写已经打开的播放器页面，需要重新搜索或选集来读取新标签。
- 清理会保留分集 ID 到来源 URL 的路由记录，便于旧选择重新获取；这些记录不作为搜索缓存命中，也不作为实际胜出来源记录。

### 升级与验证

1. 停用旧的 Forward／Rex 独立模块，导入 [logvar-1.0.17.js](../dist/logvar-1.0.17.js)。两个播放器使用同一文件，各自保存配置和缓存。
2. 根据需要重新填写 B站 Cookie、屏蔽词等配置；旧模块 ID 不同，不保证设置自动迁移。
3. 执行“清理弹幕缓存”，再重新搜索作品、选择分集，让播放器读取新 ID、来源标签和当前处理策略。

验证：已完成语法与元数据检查、Forward／Rex 两种模拟宿主回归、缓存清理及迟到写回检查、爱奇艺无计时器备用成功／失败检查。爱奇艺主／备用搜索及分集接口已做部分直连验证。以上不代表所有来源、所有作品和 Apple TV 实机加载时间均已验证。
