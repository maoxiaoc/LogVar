# 腾讯慢加载诊断与 1.0.18 修复范围

日期：2026-10-25。现象：Rex 播放《百花杀》第 4～7 集时长时间显示 0 条，第 7 集约两分钟后出现弹幕；第 1～3 集可加载。尚未取得这次 Rex 的原生运行日志，不能断言分钟级等待的具体位置。

## 直连检查

使用真实 1.0.17 模块，在本机 Node VM 中模拟 Rex 的 statusCode 返回格式，仅启用腾讯、去重间隔为 1 分钟、无已有缓存。HTTP 使用明确的直连 Agent，并在测试端设置 8 秒超时；这项测试端能力不代表 Rex 能执行相同超时。

这次接口均可用，没有复现 Rex 原生环境的两分钟等待。作品匹配成功仅确认来源与分集；整集分片、处理和回调返回完成前，播放器仍可能显示 0。不能将桌面直连速度当作 Apple TV 实机速度。

## 已复现的代码问题及修复

1. 腾讯整集方法先获取 v.qq.com 播放网页，目的仅为读取日志标题。模拟网页永不返回、弹幕接口可用时，旧包不会开始弹幕请求。播放器构建现已移除这次无关网页请求，直接获取弹幕索引与分片，Android 核心不变。
2. 当宿主传入当前集号并触发预加载时，旧包可能将一次空结果保存为十分钟预加载记录。模拟首次索引为空、下次恢复正常，1.0.17 播放仍返回 0。新版不保存空预加载；播放遇到旧版留下的空 token 时允许重新下载。该修复对所有来源的预加载生效。
3. 增加腾讯专用进度：tencent-start、tencent-index、tencent-download、tencent-data。分片在首次、每十片、最后一片及失败时记录完成数、总数、失败数和耗时，不记录 Cookie 或响应正文。没有计时器时不会额外生成定时进度。

1.0.18 直连复查第 7 集：索引 265 毫秒，81 个分片全部返回用时 444 毫秒，得到原始 48,197 条；整个播放回调 1.840 秒，去重后 29,198 条。请求共 82 次，没有播放网页请求。此为独立的一次样本，不作为精确的版本速度提升比例。

## 验证范围及下一步

已通过 Forward / Rex 模拟宿主完整回归，包含网页阻塞、空预加载重试、旧空 token 恢复、分片失败完整性及进度日志。未调整并发数量或声称 5／10／30 秒上限已能在 Rex 强制执行。当前实机慢加载可能仍涉及分片等待、宿主桥接和结果处理，需要原生日志继续区分。

导入本地 `server/dist/logvar-1.0.18.js`，清理模块弹幕缓存，再重新搜索并选择第 7 集。若仍等待很久，保存该次 Rex 日志：索引慢看 tencent-index；分片卡住看 tencent-download 的 completed/total；原始数据完成看 tencent-data；最终输出看 compare/merge 与 callback-return。模块回调已返回而页面仍迟显示时，应进一步检查宿主接收和渲染。
