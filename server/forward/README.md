## 适用范围与升级

适用于支持 JavaScript 弹幕模块的 Forward、Rex 播放器，面向 Apple TV / tvOS 使用场景。模块在播放器内通过 Widget.http 获取弹幕，无需 Android APP、电脑或 NAS 常驻。它不提供独立后台 HTTP 服务；其他客户端平台未逐一验证。

从旧版升级时，停用原 Forward／Rex 独立模块，导入通用文件，按需重新填写配置。旧模块 ID 不同，不保证设置自动迁移。两个播放器各自保存配置与缓存。

导入后执行“清理弹幕缓存”，再重新搜索作品并选择分集。修改处理策略后也需重新选集，让播放器读取当前设置对应的 ID 与来源标签。

## 弹幕处理与来源

- **合并全部来源**：合并本次完成的有效整集弹幕并去重。
- **仅保留弹幕最多的来源**：按归一化、无效项过滤、屏蔽词过滤和去重后的整集数量比较，只输出胜出来源。同数量按来源键名确定，不按填写顺序选择。
- 默认启用腾讯、爱奇艺、芒果、B站、优酷、弹弹play、人人、韩剧TV，共 8 个来源。
- **爱壹帆已从模块可用来源中移除**。旧配置中的 aiyifan 自动忽略，旧分集链接也不再触发该来源请求。Android APP 的来源不受此模块变更影响。
- 填写“启用来源”时用逗号分隔，填写内容会替换默认列表，不分优先级。未设置时使用默认来源。
- 去重间隔可直接填写 0～30 的数字，支持小数；空白默认 1，0 为精确时间去重。支持可选 B站 Cookie 和屏蔽词。

## 缓存与来源标签

成功搜索自动缓存 30 分钟，原始弹幕自动缓存 10 分钟。切换合并／最多模式复用原始数据，并按本次设置重新处理；不显示“缓存策略”参数。

“清理弹幕缓存”会同时删除搜索结果、预加载弹幕、已下载弹幕及来源标签记录，读回校验并更新刷新标记。清理前的旧搜索或弹幕任务不能重新写回有效缓存。日志以 [LogVar缓存] 标注清理范围及结果。保留分集 ID 到 URL 的路由记录，便于旧选择重新获取；它不作为搜索结果或胜出来源缓存使用。

来源使用 `from 人人&弹弹`、`【人人&弹弹】` 格式，不添加“合并”“取最多”“候选”前缀。最多模式未知时不猜测来源，加载后记录真实胜出来源。播放器提供可识别的当前集号时，可先获取该集弹幕并确定来源，再返回对应标签，播放复用同一批预加载结果。

预加载最多 4 份、合计 800 万 JSON 字符，有效期 10 分钟；其他缓存最多 8 项、合计约 200 万 JSON 字符。大条目可能不缓存。过期、清理或处理设置改变后，需重新匹配。模块不能主动更新已打开的播放器页面，重新搜索或选集后才会读取新标签。

## 加载时间与兼容

来源并发获取。首个完整有效搜索结果（含分集）后，目标再等其他来源 5 秒；首个完整有效整集弹幕后，目标再等其他来源 10 秒；全部结束则提前返回。搜索和下载各设 30 秒预算，单次请求目标最多 15 秒，临近截止缩短。超出预算后拒绝后续请求、回退和分片，迟到来源不再加入本次结果。

这些值依赖播放器能力。无计时器时只能在请求或来源返回时检查预算，不能中断卡住的在途请求；现有 Forward、Rex 检测未证明 HTTP 超时参数能按时截断，因此不能保证严格的 5／10／30 秒加载上限。合并、比较及播放器渲染也不等于网络等待耗时。

爱奇艺主搜索／分集接口返回异常时，无计时器环境最多尝试一次备用官方路径，避免在“等待 3 秒后重试”处报错；备用仍失败则结束，不循环重试。源站风控和网络故障仍可能导致无结果。

[LogVar耗时] 记录来源结果及耗时、搜索／下载、缓存命中、时间轴对齐、合并／比较、排队和回调返回。日志不包含播放器实际渲染耗时。1.0.17 已移除无法填写参数的“检测完整弹幕流程”入口及对应代码；通过正常搜索、选集和加载记录日志。

## 构建与验证

```powershell
npm ci --prefix server
npm run build-widget --prefix server
npm run test-widget --prefix server
```

构建复用本仓库来源核心和锁定依赖，最终 JS 不依赖运行时 import、Node、文件系统或 Redis。播放器构建适配不修改 Android 内嵌服务。维护旧等待行为的 1.0.8 源码可用 `npm run build-widget-legacy --prefix server` 构建。

已通过语法、元数据及 Forward／Rex 模拟宿主回归，覆盖策略切换、来源标签、缓存清理、迟到写回、分片失败和爱奇艺无计时器备用请求。部分爱奇艺主／备用接口已直连验证；尚不能据此确认所有来源或 Apple TV 实机表现。
