1.0.3 增加“媒体资料优先，标题搜索兜底”：播放器提供有效 `tmdbId`、`type` 和 `Widget.tmdb` 时，先通过 TMDB 外部 ID → IMDb → 豆瓣资料获取平台身份，再调用现有来源读取分集。剧集第二季及以后先查询该季第一集 IMDb ID，关联缺失时回退标题搜索，避免直接用整部剧 ID 误配第一季。电影不走季度查询，特别篇（第 0 季）使用标题搜索。

媒体资料直接链接目前解析腾讯、爱奇艺、优酷、B站、芒果的已支持链接格式；只有启用的来源参与。成功取得分集的平台不重复关键词搜索；其他启用来源（包括弹弹、人人）用资料中的标题补充，随后沿用原来的跨来源合并与最多来源选择。链接格式不支持、分集为空、资料接口失败或宿主缺少 TMDB 能力时，自动使用原始标题搜索。手动输入 HTTP(S) 播放链接时直接走原有链接解析。

不需要新增 TMDB API Key 或豆瓣 Cookie。IMDb 的跨季查询复用原核心的 `api.imdbapi.dev` 公共接口；豆瓣查询只读取资料。每次媒体资料搜索按本次 TMDB 身份解析，不复用仅按标题缓存的媒体身份，因此同名不同作品不会因标题缓存直接混用。该版本已通过模拟宿主的电影、季度、故障回退、来源开关、跨源合并与冷启动选集检查；新匹配链路尚未在 Forward tvOS 实机验证。

模块在 Forward 的脚本环境中执行，使用 `Widget.http` 获取弹幕，沿用本仓库的来源实现和剧集匹配逻辑。正常使用无需运行 Android 应用、电脑服务、NAS 或自行部署的 API。它不启动后台 HTTP 服务器，不能向其他应用提供 API。

## 导入和使用

1. 在 Forward 的模块管理中导入 `logvar-forward-1.0.7.js`。如果客户端只支持链接导入，需要先把该文件放到你可访问的静态文件地址，然后填写指向 JS 原文的 URL；GitHub 文件预览页不是脚本地址。静态托管只用于安装和更新，播放时不需要访问该文件地址。
2. 启用 **LogVar**，在模块参数中选择处理方式：
   - **合并全部来源**：获取已匹配到同一集的各来源整集弹幕，合并并去重。
   - **仅保留弹幕最多的来源**：比较各来源整集弹幕在格式归一化、无效项过滤、屏蔽词过滤及去重后的条数，只输出数量最多的一份；同条数时按来源键名确定结果，不按用户输入顺序或请求完成顺序选择。
3. 默认启用腾讯、爱奇艺、芒果、B站、优酷、弹弹play、人人、韩剧TV、爱壹帆。来源名称是启用集合，顺序不构成优先级。关闭来源可从 `enabledSources` 中删除其名称；修改来源后需重新搜索选集。
4. 在播放界面的弹幕搜索中选择此模块，搜索剧名并选择正确的作品和集数。修改处理方式后重新加载弹幕即可。
5. 验证时关闭 Android／电脑上的弹幕服务，检查搜索、选集、播放、快进及换集；切换其他应用或设备休眠后回到 Forward 再检查恢复行为。

## 参数

| 参数 | 说明 |
| --- | --- |
| `sourceMode` | `mergeAll`（默认）或 `most`，不提供来源优先级模式 |
| `enabledSources` | 逗号分隔的已启用来源；模块内部统一排序，与输入次序无关 |
| `bilibiliCookie` | 可选，直接填写到播放器，不会被构建进公开脚本 |
| `blockedWords` | 可选，沿用 LogVar 屏蔽词语法 |
| `groupMinute` | 相同内容合并时间窗，默认 1 分钟，范围 0～30；0 时仍移除精确时间与文本相同的重复项 |

支持的来源键名见模块参数说明。只有成功匹配到当前作品、当前分集的来源参与合并／比较，不会把同名作品或不同集数的所有搜索结果直接混合。某来源失败时保留其他来源的结果；所有来源都无数据时返回空弹幕。

首版整集获取后输出。尤其是“最多来源”模式，需要等各来源整集拉取完成后才能确定结果，因此首次加载可能较慢；没有把某一分片的数量当成整集数量。复用上游来源代码中的平台接口、镜像和备用接口，例如弹弹play使用原有 `api.danmaku.weeblify.app` 中转；无需你部署服务，但依赖这些上游接口在线，并不表示全部请求都直连平台官方域名。

## 构建和检查

在仓库根目录执行：

```powershell
npm ci --prefix server
npm run build-forward-widget --prefix server
npm run test-forward-widget --prefix server
```

可选真实接口检查（会联网请求弹弹play相关接口）：

```powershell
node server/forward/test.mjs --live
```

构建只复用 `server/package-lock.json` 已锁定的依赖，最终脚本没有运行时 import，不依赖 Node、磁盘文件或 Redis。来源核心修改后重新构建即可，不需要复制维护另一套来源代码。

离线检查用 Node VM 注入模拟 Widget，覆盖模式、计数、来源失败、不同来源格式和脚本冷启动后的搜索／选集／弹幕流程。它不能证明 Forward tvOS 的桥接兼容性或真机渲染效果。来源的节流延迟依赖宿主计时器；宿主缺少计时器时，相应路径会失败并由来源隔离处理，不使用立即执行的伪计时器。需要在目标 Forward 版本上完成导入和播放验证。
